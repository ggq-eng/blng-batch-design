核心速览

BLNG 批量出图是一套面向珠宝与钻石设计图的自动化产线。它把 BLNG 网页端「一次只能生成一张、逐张手动下载」的重复劳动，收敛成一次启动、批量产出的完整流程。使用者只需首次填写一次平台账号，其余提交描述、等待出图、下载归档、合成演示文稿等环节全部自动完成。

一、简介

BLNG（app.blng.ai）是一个在线珠宝与钻石 AI 设计平台，用户输入一段文字描述，平台就会生成对应的设计图。它的能力很强，但网页端的交互方式并不适合批量作业：每生成一张图都需要重新提交一次描述，出图之后还要手动下载保存并命名。要凑齐几十张款式图，就得把同样的动作重复几十遍。

本工具针对的正是这一段重复劳动。它通过浏览器自动化接管了中间的全部操作——自动打开页面、自动填写设计描述、自动等待出图、自动下载归档，最后再把图片合成为一份可直接使用的演示文稿。中途可以随时查看进度，也可以暂停后接着往下跑。

从定位上说，这是一套「半自动产线」而非「全无人值守服务」。账号登录环节保留人工介入的空间，批量生成、下载、命名、排版则全部自动完成。

1.1 适用的业务场景

只要是需要成批产出珠宝款式图、且不希望在重复操作上耗费人力的环节，都可以使用本工具。下表列出几类典型用法。

场景典型用法
电商选品图按品类批量出图，供选品会快速过筛
款式库扩充一次性补足某个材质或品类下的款式数量
设计灵感批量出稿同主题多版本变体，供设计师二次筛选
详情页素材生产按固定规格批量产出，直接进入排版环节

1.2 不适用的情况

本工具不负责设计决策。它只把已有的文字描述批量转成图片，描述的创意、主题、风格仍由使用者提供。此外，它依赖 BLNG 平台本身，平台策略调整会直接影响可用性，这一点在第五节「使用限制与注意事项」中说明。

下表列出工具当前具备的能力与边界，状态为「支持」的项可直接使用。

能力状态说明
单对话连续出图支持设计描述逐条自动提交，在同一任务内累积，不中断
按序命名落盘支持文件名形如 001_款式名.png，天然按序号排序
断点续跑支持已存在且体积大于 1KB 的图片自动跳过，不重复生成

需要说明的是「断点续跑」这一项的实际价值。它意味着重复执行同一区间是安全的——如果某次运行因为网络或超时而中断，直接重新启动即可，工具会自动跳过已经产出的图片，既节省时间也节省平台额度。

三、工作流程

整条流程分为四步，从准备描述清单开始，到产出演示文稿结束。前三步是批量出图的主体，第四步是收尾。

3.1 第一步：准备设计描述清单

工具以 JSON 清单作为输入，每一项包含一个款式名称和一段设计描述。清单可以自行编写，也可以由内置的提示词生成脚本自动产出——该脚本按品类、宝石、金属三个维度做组合，一次可以生成上百条结构规整的珠宝描述。若使用自有清单，只要保持字段结构一致即可。

3.2 第二步：核对账号容量

免费版账号同时只允许保留三个活跃设计项目。在开始批量任务之前，工具会先读取当前的占用情况，若已接近上限，需要先到平台网页端清理旧项目，或改用付费档账号。这一步是一次性的检查，不占用出图时间。

3.3 第三步：批量出图

这是整条流程的核心环节。工具的调度原则是「每批新建项目、全程停留在同一页面、不跨任务复用」。执行时按序号区间推进，例如先跑第 1 到第 25 条，完成后接第 26 到第 50 条，依此类推。

之所以要分批，是因为单次运行存在时长上限，整批一次跑完会在中途被强制终止。以实测速度计算，每张图大约需要一到一分半钟，每批二十五张约耗时二十五到四十分钟，是一个比较稳妥的粒度。

图片落盘目录与命名规则均已固化，无需额外配置。目录内已存在的图片会被识别并跳过，因此重复执行同一区间是安全的。

3.4 第四步：合成演示文稿

批量任务结束后，合成脚本会按自然顺序读取目录内的全部图片，一图一页写入演示文稿，版式为白底、图片居中、右下角标注页码。生成完成后脚本会自动校验页数是否与图片数量一致，并逐页比对内嵌图片的哈希值与源文件是否相同，不一致则直接报错，避免出现图页错配的低级问题。

四、使用前提

工具运行在 Windows 环境下，依赖本机浏览器与两个运行时。下表列出完整的前置要求。

项目要求说明
操作系统Windows依赖本机浏览器的调试端口
浏览器Microsoft Edge复用本机已安装的 Edge，无需额外安装 Chrome
平台账号BLNG 账号交付包内账号密码为空，需使用方自行填写一次
Python3.10 及以上执行自动化脚本，需包含网络通信相关依赖
Node.js18 及以上仅合成演示文稿时需要
网络可直连 BLNG若本机启用了系统代理，脚本已内置回环排除配置

关于账号，需要特别说明一点：交付包中的账号与密码字段默认是空白的，不含任何真实凭据。使用方首次运行时填写自己的账号，之后可由本地会话文件维持登录状态，无需重复输入。也可以通过环境变量注入账号密码，这种方式不会在代码文件中留下痕迹，适合多人共用一台机器的场景。

五、使用限制与注意事项

本节列出使用前必须了解的限制条件。这些不是可以绕过的细节，而是由平台策略与运行环境共同决定的硬约束。

限制具体表现应对方式
活跃项目数量上限免费版同时最多三个设计项目跑批前先清理，或改用付费档账号
历史项目会被清理免费档项目存放一段时间后消失已开跑的任务不要跨天续跑，尽量一次完成
单次运行时长上限单条命令最长运行约十分钟按二十五到五十张为一档分批推进
生成速度受限每张约一到一分半钟按实际时间预算规划批次规模
内容重复可能偶发产出与前面重复的图工具自动检出并重跑，无需人工处理

  其中「历史项目会被清理」是最容易踩的一条。免费档的项目并非永久保留，若上午跑了一半、下午再想接着跑，很可能发现原项目已经不在，只能重新开始。因此建议在一次连续的时间段内完成整批任务。

关于生成速度，需要建立合理的预期。免费版并没有每日总量上限，限制在于并发能力而非产出总量，所以完成两百张以上的任务在技术上是可行的，只是需要相应的时间投入——按每张一分半钟的保守估计，两百五十张大约需要六个小时。这一点在制定计划时应当提前纳入考虑。

六、成果输出

任务完成后会得到两份成果，均落在预先设定的目录下。

第一份是图片文件夹，里面是按序号命名的全部设计图，文件名形如 001_项链.png、002_戒指.png。三位补零的编号保证了在文件管理器中按名称排序时顺序正确，即使总数超过一百张也不会错乱。

第二份是演示文稿，每页一张图，右下角标注页码。这份文件可以直接用于会议展示、客户提案或内部评审，不需要再手工整理。若后续更换或补充了图片，重新执行合成脚本即可覆盖重建。

八、常见问题

以下是最常被问到的几个问题，按使用顺序排列。

问：图片保存在哪里？

答：保存在预先设定的设计图目录下；演示文稿与图片目录同级。如需变更位置，可以显式指定其他目录。

问：中途中断了要重新开始吗？

答：不需要。重新启动后工具会跳过已经产出的图片，接着上次的进度继续。

问：同一批任务可以重复执行吗？

答：可以。已存在且体积正常的图片会被自动跳过，重复执行不会造成重复产出，也不会额外消耗平台额度。

问：生成结果会有重复吗？

答：偶有发生。工具会检出与已有内容重复的图片并自动重跑该条，无需人工介入。

问：一次跑多少张比较合适？

答：建议每批二十五到五十张。这个区间既能保证在单次运行时长上限内完成，也便于中途检查产出质量。

问：支持其他操作系统吗？

答：当前版本以 Windows 为运行环境。工具依赖本机浏览器的调试端口，跨平台适配需要额外验证。
